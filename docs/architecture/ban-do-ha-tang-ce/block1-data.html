3. Hai đường đọc ticker + bẫy TICKER_SOURCE

Đường FILE

KaggleDataLoader.loadDailyTickersShort(dayTs) :101-124

Đọc .bin.gz trong IMPORT_DIR="kaggle_data_hpo/" (relative CWD, hardcode). Dùng cho backtest/WFO khi TICKER_SOURCE=file (Kaggle self-contained).

Đường AEROSPIKE

DataManagerAerospikeFloatSim.readDataFromAerospikeCustom(startTime,totalMinutes) :1059-1154

Đọc set kline_1m_opt qua getReadClient() (chọn theo AEROSPIKE_READ_CLUSTER). Dùng cho export feature/market, và sim khi TICKER_SOURCE=aerospike.

⚠ SỰ THẬT quan trọng — bản NotebookLM SAI ở đây Configs.java:87: public static String TICKER_SOURCE = properties.get("TICKER_SOURCE"); — CHỈ đọc config.properties, KHÔNG có fallback System.getenv. ⇒ Truyền TICKER_SOURCE=file qua env khi launch job (Kaggle/HPO/Oracle) bị bỏ qua hoàn toàn. Muốn đổi phải sửa đúng config.properties của box. (Đã xác nhận: stage2_frozen_ab.sh ghi header "TICKER_SOURCE=file" nhưng thực tế đọc Aerospike vì config Oracle là aerospike.)
Gotcha IMPORT_DIR KaggleDataLoader.IMPORT_DIR = "kaggle_data_hpo/" (root, relative CWD) — nhưng file ticker thật nằm ở kaggle_data_hpo/daily/. Nếu thực sự bật TICKER_SOURCE=file trên Oracle sẽ KHÔNG tìm thấy file (loader trả null, tầng trên fail-fast "khong co ticker → DUNG NGAY"). Cần symlink hoặc env-hoá IMPORT_DIR. INFRA_FACTS.md:24-27
