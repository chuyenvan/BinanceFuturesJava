Phân bổ tài nguyên & task

Oracle (compute chính)

  • TỐI ĐA 3 job Java đồng thời (sự cố thật 07-24: 4 worker → SSH/CE đơ → phải reboot)
  • wfo_fanout default 2 Oracle worker · RAM guard 3GB + buffer 3GB
  • KHÔNG chạy 2 WFO nặng cùng lúc (fail thật: trailfan 9/16 FAILED + zombie JVM)
  • Disk 89% (~17.6GB free) — self-gate trước job ghi nhiều

Kaggle (fleet)

  • 5 kernel song song (cap 5) · file-mode · session 12h hard-kill
  • extra_env KHÔNG áp cho Kaggle (env baked) → flag mới phải bump kernel dataset
  • Resource cap Lớp 1: {local:1, oracle:4, heavy_226:1, kaggle:5, kaggle_distributed:1}, global 6

Task claim / handoff (rules/task-workflow.md + supervisor.py)

  • Headless (supervisor): claim atomic os.mkdir(locks/<id>); supervisor là single-writer của runtime_state.json/STATUS.md/field status. Worker chỉ làm task + ghi report.
  • Chạy tay (CDK): tự ghi owner+status:DOING+updated vào header task; DOING+updated còn mới → không đụng; DOING+updated >2h nghi reset → STALE reclaim được.
  • Bàn giao job nền (bắt buộc): ghi vào tasks/<id>.md: kernel slug/PID+host, lệnh+jar+args+dataset/env, output path, cách check, bước còn lại.
  • Output contract (mọi worker kết bằng block này):
=== RESULT ===
STATUS: DONE | REVIEW | NEEDS_HUMAN | FAILED
COMMIT: <hash | ->
ARTIFACTS: <path | ->
VERIFY: <số đối chiếu acceptance | ->
DECISIONS: <quyết định reversible đã tự ra | ->
QUESTIONS: <gom 1 lần | ->
=== END ===

Thiếu/sai format → NEEDS_HUMAN (không đoán). Retry > max (2) → NEEDS_HUMAN; reap stale khi elapsed > TIMEOUT hoặc idle >20'. Bất biến cứng: touches_live_process=true → KHÔNG BAO GIỜ auto; Fable bị CẤM làm WORKER_MODEL.
